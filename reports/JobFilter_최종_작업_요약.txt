JobFilter 최종 작업 요약: 어떻게 했고, 무엇을 해결했는지
=====================================================================

이 문서는 JobFilter 프로젝트를 정리하면서 한 작업과 해결한 일들을
실제 프로젝트를 진행한 사람이 다른 사람에게 설명하듯이 기록한 것입니다.
"어떻게 했는지"와 "왜 이렇게 했는지", "무엇이 해결되었는지"를 함께 담았습니다.


0. 전체 방향
------------
JobFilter를 단순 공고 목록 서비스에서
"지원 건 하나를 끝까지 준비할 수 있는 취업 준비 플랫폼"으로 발전시키는 것을
목표로 했습니다.

핵심 사용자는 학생이고, 핵심 가치는
"맞춤 공고 발견 → 지원 목록 관리 → 자소서/면접/포트폴리오 준비 → 알림/일정"으로
이어지는 하나의 흐름입니다.

리크루터 기능은 사용자 흐름에서 제거했고,
AI API 없이 rule 기반으로 핵심 기능을 구현했습니다.


1. 디자인 시스템 정비
---------------------
### 어떻게 했는지
- `app/globals.css`의 oklch 값을 HSL로 바꾸고 `tailwind.config.ts`와 매핑했습니다.
- `#0f172a` 같은 하드코딩 색상을 `bg-primary`, `bg-slate-900` 같은
  시맨틱 토큰으로 교체했습니다.
- `text-[10px]`, `w-4.5`, `rounded-4xl` 같은 비표준 Tailwind 클래스를 정리했습니다.
- `components/layout/Sidebar.tsx`의 이모지를 lucide 아이콘으로 통일했습니다.
- 지원 상태 색상을 `lib/status-config.ts`에 모아 중앙 관리했습니다.

### 해결된 것
- Brand Zone(랜딩/인증)과 Work Zone(대시보드/관리자)의 시각적 구분이 생겼습니다.
- 색상, 아이콘, 상태 표현이 토큰화되어 페이지를 추가하거나 리팩터링할 때
  일관성을 깨뜨리지 않고 재사용할 수 있게 되었습니다.

9. lint 경고 수정
-----------------
### 어떻게 했는지
- Next.js TS plugin이 경고하는 server action prop 이름을 변경했습니다.
  - `onPageChange` → `onPageChangeAction`
  - `onChange` → `onChangeAction`, `onReset` → `onResetAction`
  - `onStatusChange` → `onStatusChangeAction`, `onDelete` → `onDeleteAction`
- `Button`, `AlertDialog`에서 발생한
  `Function components cannot be given refs` 경고를 수정했습니다.
  - `components/ui/button.tsx`: `React.forwardRef`
  - `components/ui/alert-dialog.tsx`: Overlay/Content/Trigger/Header/Footer/
    Media/Title/Description → `React.forwardRef`
- `/interview` 질문 추가 Dialog의 `DialogDescription` 누락을 추가했습니다.

### 해결된 것
- `npx tsc --noEmit`, `npm run lint`, `npm run test`가 모두 통과합니다.
- 브라우저 console에서 React ref/accessibility 경고가 사라졌습니다.

- `/interview` 질문 답변 저장과 모의 면접
- `/calendar` 월 이동 및 일정 상세
- `/admin/listings`, `/admin/users`, `/admin/bulk-jobs` 등 관리자 CRUD

### 차주(15주차) 권장 계획 (P0)
1. Portfolio, InterviewAnswer, Experience에 `jobId` 추가 및
   `/api/jobs/[id]`에서 연결 자료 조회
2. `lib/auth.ts`로 권한 헬퍼 통일 및 DTO 반환 표준화
3. User, JobPosting, Portfolio 응답에서 민감 필드 제외
4. GitHub 외부 요청에 timeout, redirect, rate limit, 캐싱 적용
5. 관리자 벌크 등록에 transaction과 실패 행 CSV 다운로드
6. UserNotification에 type, referenceId, actionUrl, 중복 방지 기준 추가
