3. build 실패 해결
================================================================================

3-1. app/api/dashboard/route.ts

이 라우트는 getServerSession을 사용하는데, Next.js 14의 static prerender 단계에서
request headers에 접근하면 build가 실패한다. 이 문제를 피하기 위해 라우트 파일 상단에
export const dynamic = 'force-dynamic'를 추가하여 해당 API가 요청 시점에만
렌더링되도록 했다.

3-2. app/open/listings/page.tsx

이 페이지는 client 컴포넌트에서 useSearchParams를 사용하고 있다. Next.js 14에서는
useSearchParams가 static build 단계에서 CSR bailout을 유발할 수 있으므로, 페이지를
React Suspense boundary로 감싸서 build 오류를 막았다. 기존에 추가되어 있던
export const dynamic = 'force-dynamic'는 client page에서 의미가 없어 제거했다.

3-3. app/api/admin/**/*.route.ts

관리자 API 중 getServerSession이나 headers를 사용하는 10개 라우트에서 동일한
static prerender 오류가 발생할 수 있었다. 각 파일에 export const dynamic =
'force-dynamic'를 추가하여 /api/admin/stats, /api/admin/reports 등이 정상적으로
build되도록 했다.

변경했다.

- components/cover-letter/ExperienceLibrary.tsx: onInsert -> onInsertAction
- app/(dashboard)/portfolio/page.tsx: PortfolioForm 호출 prop 이름 변경
- app/(dashboard)/cover-letter/page.tsx: ExperienceLibrary 호출 prop 이름 변경

15-3. 발견한 문제 및 픽스

[문제 1] /jobs/[id]에서 연결 자료가 바로 갱신되지 않음

원인은 포트폴리오/경험/면접 저장 후 React Query 캐시의 ['job', id]가 무효화되지
않아 stale 데이터가 노출되는 것이었다. 사용자가 job 상세 페이지를 먼저 열어본
뒤, 다른 페이지에서 자료를 연결하고 다시 돌아오면 캐시된 빈 데이터가 보이게 된다.

해결 방법은 저장 성공 시 queryClient.invalidateQueries({ queryKey: ['job'] })를
추가하는 것이다. 이 변경을 아래 파일에 적용했다.

- app/(dashboard)/portfolio/page.tsx
- components/cover-letter/ExperienceLibrary.tsx
- components/interview/AnswerSlideOver.tsx

[문제 2] /api/jobs 목록/생성 API 응답에 userId 노출

GET /api/jobs와 POST /api/jobs는 지금까지 sanitizeJobPosting()을 거치지 않아
userId가 응답에 그대로 포함되고 있었다. lib/api.ts의 sanitizeJobPosting()을
app/api/jobs/route.ts에 적용하여 응답에서 userId를 제거했다.
