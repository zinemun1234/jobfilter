03

지원 공고와 자료 연결

사용자가 포트폴리오, 경험, 면접 답변을 작성할 때 어떤 지원 공고와 관련 있는지 선택할 수 있게 했다. 상세 페이지에서는 연결된 자료를 한눈에 볼 수 있다.

데이터 모델 변경

Prisma 스키마에 jobId 추가. Portfolio, Experience, InterviewAnswer와 JobPosting 간의 관계를 정의하고 migration 20260813000000_add_job_id_links 생성.

API 확장

portfolio, experiences, interview/answers API에서 jobId 저장/수정을 지원. /api/jobs/[id] 응답에 연결된 자료 포함.

UI 추가

PortfolioForm, ExperienceLibrary, AnswerSlideOver에 /api/jobs 조회 드롭다운 추가. /jobs/[id]에 "연결된 준비 자료" 섹션 추가.

04

API 보안 및 인증 통일

관리자 API가 각자 session 체크를 하고 있었기 때문에 패턴이 달랐다. lib/api.ts의 requireAdmin()과 sanitizeJobPosting()으로 통일했다.

권한/인증

  • requireAdmin(): 관리자 권한 확인 후 { userId, role } 반환
  • requireAdminOrOwner(): 소유자 또는 관리자 통과
  • 15개 관리자 API에 적용

DTO 변환

  • sanitizeUser(): password 제거
  • sanitizeJobPosting(): userId, user 제거
  • /api/jobs, /api/jobs/[id] 응답에 적용
파일변경 내용
app/api/jobs/route.tsGET/POST 응답 sanitizeJobPosting() 적용
app/api/jobs/[id]/route.tsGET/PUT/PATCH/POST 응답에서 userId 제거, 연결 자료 포함

06

E2E 확인

브라우저에서 /jobs -> /portfolio -> /cover-letter -> /interview -> /jobs/[id] 순서로 흐름을 확인했다. 포트폴리오, 경험, 면접 답변에 공고를 연결하고, 상세 페이지에서 표시되는 것을 확인했다.

문제: /jobs/[id] 연결 자료가 바로 갱신되지 않음

포트폴리오/경험/면접 저장 후 React Query 캐시의 ['job', id]가 무효화되지 않아 stale 데이터가 노출됨.

queryClient.invalidateQueries({ queryKey: ['job'] }) 추가

문제: /api/jobs 응답에 userId 노출

GET/POST /api/jobs가 sanitizeJobPosting()을 거치지 않아 userId가 클라이언트로 내려감.

app/api/jobs/route.ts에 sanitizeJobPosting() 적용
