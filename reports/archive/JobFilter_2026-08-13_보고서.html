연결 자료 UI 흐름

1. 지원 공고 등록 /jobs
2. 포트폴리오 연결 /portfolio
3. 경험 연결 /cover-letter
4. 면접 답변 연결 /interview

각 입력 폼에서 /api/jobs를 조회해 지원 공고 목록을 드롭다운으로 제공한다. 사용자가 공고를 선택하면 해당 jobId가 포트폴리오, 경험, 면접 답변과 함께 저장된다. 저장 후 /jobs/[id] 페이지의 "연결된 준비 자료" 섹션에서 포트폴리오, 경험, 면접 답변 목록을 확인할 수 있다.

E2E 확인 및 발견 문제

브라우저에서 /jobs -> /portfolio -> /cover-letter -> /interview -> /jobs/[id] 순서로 사용자 흐름을 확인했다. 포트폴리오, 경험, 면접 답변에 공고를 연결하고, 지원 공고 상세 페이지에서 연결된 자료가 표시되는 것을 확인했다.

발견한 문제 1: /jobs/[id]에서 연결 자료가 바로 갱신되지 않음

원인은 포트폴리오/경험/면접 저장 후 React Query 캐시의 ['job', id]가 무효화되지 않아 stale 데이터가 노출되는 것이었다. 사용자가 job 상세 페이지를 먼저 열어본 뒤, 다른 페이지에서 자료를 연결하고 다시 돌아오면 캐시된 빈 데이터가 보이게 된다.

해결: 저장 성공 시 queryClient.invalidateQueries({ queryKey: ['job'] })를 추가하여 job 상세 캐시를 갱신하도록 변경했다.

발견한 문제 2: /api/jobs 응답에 userId 노출

GET /api/jobs와 POST /api/jobs는 sanitizeJobPosting()을 거치지 않아 userId가 응답에 그대로 포함되고 있었다. lib/api.ts의 sanitizeJobPosting()을 app/api/jobs/route.ts에 적용하여 응답에서 제거했다.
