JobFilter 작업 요약: 어떻게 했고, 뭘 했고, 왜 이렇게 했는지
=====================================================================

이 문서는 JobFilter 프로젝트를 정리하고 기능을 완성하면서 변경한 내용을
개발자가 다른 사람에게 설명하듯이 기록한 것입니다.
가능하면 “왜 이렇게 했는지”도 함께 담아두었습니다.


1. 디자인 시스템 정비
---------------------
프로젝트 전체에 걸쳐 색상, 아이콘, 상태 표현이 제각각이었는데,
UI/UX 계획서에서 정한 Brand Zone(랜딩/인증)과 Work Zone(대시보드/관리자) 구분을
따를 수 있도록 먼저 디자인 토큰을 정리했습니다.

구체적으로 한 일은 다음과 같습니다.
- `app/globals.css`의 oklch 값을 HSL로 변환하고 `tailwind.config.ts`와 매핑했습니다.
- `#0f172a` 같은 하드코딩된 색상을 `bg-primary`, `bg-slate-900` 같은
  시맨틱 토큰으로 바꿨습니다.
- `text-[10px]`, `w-4.5`, `rounded-4xl`처럼 Tailwind에 없거나 비표준인
  클래스를 정리했습니다.
- `components/layout/Sidebar.tsx`에 흩어져 있던 이모지를 lucide 아이콘으로 통일했습니다.
- 지원 상태 색상(`PREPARING` ~ `REJECTED`)을 `lib/status-config.ts`에 모아
  한곳에서 관리하도록 했습니다.

이렇게 한 이유는, 색상과 아이콘, 상태 표현이 토큰화되어야 나중에 페이지를
추가하거나 리팩터링할 때 일관성을 깨뜨리지 않고 재사용할 수 있기 때문입니다.
또한 랜딩/인증과 대시보드/관리자의 영역 구분이 시각적으로 명확해집니다.


2. 메인 랜딩 페이지 디자인
--------------------------
랜딩 페이지도 Brand Zone 다크 테마로 개선했습니다.

변경한 내용:
- `app/page.tsx`에 반응형 히어로, 학과 연결 배너(`from=info/aisw` 분기),
  공고 미리보기, 핵심 기능 소개, 사용 흐름, 학과 연동, 푸터를 추가했습니다.
- 모바일에서는 히어로 타이틀을 `text-4xl`로 키우고 공고 카드를 1열로,
  CTA 버튼은 전체 폭으로 잡았습니다.

이유:
- 단순히 어둡게 보이는 게 아니라, 비로그인 방문자가 서비스 가치를
  바로 느끼고 로그인/공고 탐색 같은 행동으로 이어지도록 설계했습니다.
- Prisma 조회 로직(활성 공고 수, 최신 4개)은 그대로 두어
  기능은 유지하고 스타일과 구조만 개선했습니다.


3. 기능 감사 및 우선순위 추천
-------------------------------
전체 페이지와 스키마를 훑어보면서 제거/개선/추가할 후보를 정리했습니다.

당장 우선순위가 높다고 판단한 3가지는:
1. 리크루터 기능 숨김
2. 공고 1클릭 지원 추가
3. 마감/신규 공고 알림 기능

이유:
- 핵심 사용자는 학생이고, 핵심 가치는 “맞춤 공고 + 자소서 코칭”입니다.
  Recruiter, GitHub 분석, Embed 위젯 같은 기능은 당장 운영 흐름에 맞지 않거나
  오버헤드가 클 수 있다고 봤습니다.
- 반대로 위 3가지는 실제 사용 흐름에서 피로를 가장 줄여주는 기능이라
  먼저 구현하기로 결정했습니다.


4. 1순위 기능 구현
-------------------

4-1. 리크루터 기능 숨김
리크루터 기능은 노출되지 않도록 막되, DB나 페이지 파일을 완전히 제거하지는
않았습니다.

변경한 내용:
- `next.config.js`에 redirects를 추가했습니다.
  - `/register-recruiter`, `/recruit` → `/`
  - `/recruiter` → `/dashboard`
- `app/(auth)/login/page.tsx`, `app/(auth)/register/page.tsx`에서
  “기업 회원가입 (RECRUITER)” 링크를 제거했습니다.
- `components/layout/Sidebar.tsx`에서 RECRUITER 메뉴와 RECRUITER 뱃지를
  제거했습니다.

이유:
- 외부 리크루터가 실제로 사용되지 않는다면 노출/보안 관리 포인트만
  늘어나기 때문입니다.
- DB 스키마와 기존 페이지를 삭제하지 않고 접근만 막아,
  나중에 다시 열릴 가능성을 열어뒀습니다. 완전 삭제는 별도로 진행하면 됩니다.


4-2. 공고 1클릭 지원
비로그인 방문자가 메인이나 공개 공고에서도 쉽게 지원 흐름으로 들어갈 수
있도록 `components/jobs/ApplyButton.tsx`를 새로 만들었습니다.

변경한 내용:
- `useSession`으로 로그인 상태를 확인합니다.
- 비로그인: “로그인 후 지원” 링크로 `/login`을 보여줍니다.
- 로그인: “지원하기” 버튼 클릭 시 `POST /api/listings`로 `JobPosting`을 생성합니다.
  중복(409) 또는 성공 시 “추가됨”으로 상태를 바꿉니다.
- 메인 랜딩 미리보기 카드와 `/open/listings`에 `ApplyButton`을 적용했습니다.
- `/listings`, `/listings/[id]`, `/bookmarks`의 기존 “추가” 버튼은
  그대로 유지했습니다.

이유:
- `/listings`, `/listings/[id]`에는 이미 추가 기능이 있었지만,
  비로그인이 보는 메인과 `/open/listings`에는 진입점이 없었습니다.
- `ApplyButton`을 재사용 컴포넌트로 만들어 여러 페이지에서 동일한 동작과
  디자인을 유지했습니다(DRY, 일관성).
- 비로그인 유저에게는 로그인 유도, 로그인 유저에게는 즉시 지원 목록 추가를
  제공합니다.


4-3. 마감/신규 공고 알림
`lib/notifications.ts`를 새로 만들어 알림 생성 로직을 한곳에 모았습니다.

변경한 내용:
- `syncJobNotifications(userId)`: 대시보드 진입 시 마감 D-3, 면접 D-2,
  지원 14일 후 팔로업 알림을 생성합니다.
- `notifyUsersOfNewListing(listing)`: 관리자가 수동 등록하면 전체 알림을 보냅니다.
- `notifyUsersOfNewListingsSummary(count)`: 일괄 등록 시 요약 알림을 보냅니다.
- `app/(dashboard)/dashboard/page.tsx`에서 `syncJobNotifications()`를
  자동으로 호출합니다.
- `app/api/admin/listings/route.ts`, `/bulk/route.ts`에 신규 공고 알림 연결.
- 기존 `/api/notifications/sync` 라우트도 `lib/notifications.ts`의
  `syncJobNotifications()`를 사용하도록 통합.

이유:
- 마감 임박 알림을 생성하는 `POST /api/notifications/sync` API가 이미
  있었지만, 사용자가 수동으로 눌러야만 동작했습니다.
- 대시보드에 진입할 때마다 자동으로 동기화되게 연결해
  사용자가 알림을 놓치지 않도록 개선했습니다.
- 신규 공고 알림은 관리자가 등록하는 시점에 자동 발송되어
  사용자 참여율을 높입니다.
- 기존 알림 API와 중복/불일치를 막기 위해 `lib/notifications.ts`로
  단일 진실 공원(SSOT)을 만들어 유지보수성을 확보했습니다.

- shadcn/ui 토큰(`bg-primary`, `text-foreground`, `border-border` 등)으로
  변경해 랜딩/인증/대시보드 간 색상 체계가 일관되게 유지되도록 했습니다.
