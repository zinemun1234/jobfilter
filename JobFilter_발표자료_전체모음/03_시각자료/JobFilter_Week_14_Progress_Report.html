03 / Current Status기능별 실제 상태

현재 구현 상태는 다섯 단계로 나눠 봤습니다.

화면에 버튼이 있는 것과 실제 데이터가 완전히 연결된 것은 다르기 때문에, 모델·API·화면이 모두 연결된 경우와 추가 검증이 필요한 경우를 구분했습니다.

분류주요 기능판단
현재 구현공고 탐색·검색·북마크, 지원 현황·칸반·상태 이력, 알림, 자소서 CRUD·분석·버전 비교, 경험 저장소, 포트폴리오 CRUD, 면접 질문·답변, 캘린더, 로드맵, 관리자 업로드핵심 화면과 API가 연결되어 있습니다.
1차 구현지원 건 Command Center, 지원 준비율, 자소서와 지원 건 연결, 모의 면접 UI, 관리자 dry-run 후 선택 등록기본 흐름은 가능하지만 직접 집계·운영 검증이 남아 있습니다.
보완 필요포트폴리오·면접 답변 연결, 준비율 개선, API 권한·DTO, 알림 구조, 관리자 업로드 원자성, GitHub 요청 보호다음 개발 우선순위입니다.
향후 계획회사·공고 조사 노트, 면접 회고, 기술 증거 매핑, ATS 체크리스트, 지원 활동 분석, 공고 변경 감지기획과 모델 설계 후 진행합니다.
제외별도 Today’s Tasks 페이지, AI 자동 생성·음성 면접, Chrome extension, Gmail/LinkedIn 연동현재 개발 범위에서는 제외했습니다.
핵심 판단: JobFilter는 기능이 없는 서비스가 아니라, 기능을 지원 건 하나에 직접 연결하는 작업이 남은 서비스입니다.

04 / Technical Findings삭제 · 개선 · 신규 제안

다음 작업은 세 가지 방향으로 정리했습니다.

삭제 또는 비활성화

운영 준비가 되지 않은 기능

  • 이메일 발송 없이 토큰을 노출하는 비밀번호 재설정 흐름
  • timeout·rate limit 보호가 없는 GitHub 자동 분석
  • 중복된 lib/roadmapTemplates.ts 파일
  • 원인 해결 없이 사용하는 as unknown as 타입 캐스팅
개선

기존 기능을 안전하게 연결

  • Portfolio·InterviewAnswer·Experience에 jobId 추가
  • requireAdmin·requireOwner 등 권한 함수 통합
  • Prisma 객체 전체 반환 대신 DTO 사용
  • JSON 문자열 필드 공통 파싱 헬퍼 정리
  • 관리자 벌크 등록 transaction 적용

새로 추가할 차별화 기능

지원 건 통합 워크스페이스

관련 자소서·포트폴리오·면접 답변·경험·일정·노트를 한 화면에 표시합니다.

회사·공고 조사 노트

지원 동기, 기업 분석, JD 키워드, 예상 질문을 지원 건과 함께 관리합니다.

면접 회고

면접 회차, 자신감, 예상 밖 질문, 피드백과 개선점을 기록합니다.

기술 증거 매핑

JD의 요구 기술을 어떤 경험·포트폴리오·로드맵으로 증명하는지 보여줍니다.

외부 사례를 참고한 결론: Jobotrak, JobHunt, ApplyArc, ApplyWave, Jobscan, Prentus 등도 단순 공고 목록보다 지원 건 단위의 맥락 연결과 증거 확인을 중요하게 보고 있습니다. JobFilter는 이를 AI API 없이 rule-based 방식으로 구현하는 방향입니다.

05 / AI Decision현재 미적용 사유

AI는 현재 적용하지 않기로 했습니다.

이것은 구현이 불가능해서가 아니라, 현재 단계에서는 비용·정확성·개인정보·개발 우선순위를 고려했을 때 rule-based 방식이 더 적절하다고 판단했기 때문입니다.

운영 비용

학생 대상 무료 서비스에서 LLM API를 사용하면 지속적인 토큰 비용이 발생합니다. 현재 방식은 서버 비용 부담이 낮습니다.

정확성과 오해

AI 피드백을 합격 가능성으로 오해할 수 있습니다. 현재는 합격 판정이 아닌 작성 보조 피드백에 집중합니다.

개인정보와 윤리

자소서·면접 답변·경험은 민감정보입니다. 외부 전송 전 동의·보관·삭제·감사 정책이 필요합니다.

현재 우선순위

AI보다 지원 현황·자소서·면접·포트폴리오의 데이터 연결과 API 보안 통일이 먼저입니다.

AI 도입은 완전히 닫아둔 것이 아니라, 룰 기반 데이터와 개인정보 정책, 비용 모델이 준비된 뒤 점진적으로 검토할 계획입니다.
현재 원칙: 매칭 점수는 합격 가능성이 아니라 참고 지표입니다. 자소서 분석은 AI 합격 판정이 아니라 작성 보조 피드백입니다.

Closing Statement
JobFilter는 공고를 보여주는 데서 끝나지 않고, 지원 건 하나에 공고·자소서·경험·면접·포트폴리오·일정을 연결하는 취업 준비 플랫폼입니다.

다음 단계는 기능을 더 많이 만드는 것이 아니라, 이 연결을 실제 데이터와 안전한 API 구조로 완성하는 것입니다.

최종 목표
“이 공고에 지원하려면 어떤 증거를 준비해야 하는가”를 보여주는 서비스로 발전합니다.
