1. 이 프로젝트는 무엇인가? (WHAT)
================================================================================

JobFilter는 컴퓨터공학부 학생을 위한 "맞춤 취업 공고 필터링 & 자소서 코칭 웹 애플리케이션"이다.

- 학교 취업지원처에서 받은 엑셀/CSV 파일을 업로드하면, 개발·IT·보안·데이터·기획 직군 공고만 자동으로 추출한다.
- 학생은 자신의 기술 스택을 등록하고, 공고와의 매칭률, 마감 D-day, 우선순위 점수를 확인한다.
- AI를 사용하지 않고 키워드/룰 기반으로 자소서를 코칭한다. (서버 비용 0원 원칙)
- 지원 현황, 면접 준비, 기술 스택 로드맵, 포트폴리오 분석, 북마크, 캘린더, 공지/알림 등의 기능을 제공한다.
- 관리자(ADMIN)는 공고를 업로드/관리하고, 학생을 관리하며, 통계와 공지를 볼 수 있다.
- 리크루터(RECRUITER)는 기업 입장에서 학생 프로필을 조회하거나 공고를 직접 등록할 수 있다(관리자 승인 필요).

실제 배포 URL: https://jobfilter-woad.vercel.app
운영 기간: 2026.05.22 ~
대상 학과: 안산대학교 컴퓨터정보과, 인공지능소프트웨어과

2. 왜 만들어졌는가? (WHY)
================================================================================

2-1. 해결하려는 문제
--------------------
- 학교 취업지원처에서 제공하는 엑셀 파일에는 CS(컴퓨터공학)와 무관한 직군도 섞여 있다.
- 학생들이 직접 필터링하기 번거롭고, 자신의 기술 스택과 맞는 공고를 놓치기 쉽다.
- 자기소개서 작성 시 어떤 부분이 약한지, STAR 기법이나 수치 포함 여부 등을 스스로 판단하기 어렵다.
- AI 기반 자소서 코칭은 API 비용이 발생하고, 학생 개개인에게 지속적으로 무료로 제공하기 부담스럽다.
- 취준 준비물(서류, 포트폴리오, 자격증 등)을 여러 공고별로 관리하기 어렵다.

2-2. 설계 철학
--------------------
- AI 사용 금지 / 서버 비용 0원 원칙
  : 자소서 코칭, 공고 필터링, 키워드 추출, 우선순위 산정 등 핵심 기능을 모두
    키워드 매칭, 정규표현식, 룰 기반으로 구현했다.
- 학과 맞춤형
  : 컴퓨터공학부/AI소프트웨어과 학생의 기술 스택과 목표 직무에 최적화된 정보 제공.
- 프라이버시 보호
  : 리크루터에게 보여지는 프로필은 마스킹하여 미리보기 가능.
- 실무 중심 취업 준비
  : 공고뿐 아니라 지원 현황, 체크리스트, 면접, 로드맵, 포트폴리오 분석까지 통합 지원.

3. 왜 이런 방식으로 만들었는가? (WHY THIS APPROACH)
================================================================================

3-1. 기술 스택 선정 이유
------------------------
- Next.js 14 (App Router)
  : 하나의 코드베이스로 SSR/CSR/API Routes를 모두 처리할 수 있어 학교/소규모 팀 운영에 적합.
- React + TypeScript
  : 컴포넌트 기반 UI + 타입 안정성 확보.
- Tailwind CSS + shadcn/ui
  : 빠른 UI 개발, 일관된 디자인 시스템, Radix UI 기반 접근성.
- Prisma + PostgreSQL(Supabase)
  : 타입 안전한 ORM, 무료 PostgreSQL 호스팅, Vercel 배포 환경과의 친화성.
- NextAuth.js (Credentials)
  : 이메일+비밀번호 방식이 학생들에게 가장 익숙하고 별도 외부 인증 서비스 의존 최소화.
- zustand + @tanstack/react-query
  : 클라이언트 상태와 서버 상태를 분리하여 관리.
- recharts
  : 자소서 점수 변화, 대시보드 활동 통계 등 차트 시각화.
- xlsx
  : 엑셀/CSV 파싱.
- vitest
  : 테스트 자동화.

3-2. AI를 쓰지 않은 이유
------------------------
- OpenAI/Claude 등 외부 API 사용 시 월간 비용 발생.
- 학생 대상 서비스에서 무료로 지속 운영하려면 비용 구조가 중요.
- 취업 자소서의 핵심 피드백(분량, STAR, 직군 키워드, 수치, 공허한 표현, 문장 길이, 협업 등)은
  충분히 룰 기반으로 구현 가능하다고 판단.

3-3. 역할 기반 접근 제어
------------------------
- USER / ADMIN / RECRUITER 3가지 역할로 기능을 구분.
- middleware.ts에서 JWT 토큰의 role을 확인하여 /admin, /dashboard 등 보호된 경로 접근 제어.

4. 어떻게 만들었는가? (HOW)
================================================================================

4-1. 인증 시스템
----------------
파일: lib/auth.ts, middleware.ts
- NextAuth.js CredentialsProvider로 이메일+비밀번호 로그인 구현.
- bcryptjs로 비밀번호 해싱 및 검증.
- JWT 세션 전략 사용, 세션에 user.id, user.role 포함.
- middleware.ts에서 로그인 여부 및 역할(ADMIN) 체크 후 리다이렉트.

4-2. 공고 필터링 및 업로드
--------------------------
파일: app/api/admin/listings/upload/route.ts, lib/job-tags.ts
- 관리자가 엑셀(.xlsx) 또는 CSV 파일 업로드.
- xlsx 라이브러리로 파싱, 다양한 컬럼명(회사명, 기업명, 직무, position, 마감일, deadline 등)을
  유연하게 매핑(mapRow 함수).
- 엑셀 날짜 시리얼 숫자도 JS Date로 변환.
- CS_KEYWORDS 배열을 기준으로 개발/IT/보안/데이터/기획/사무 관련 공고만 필터링.
- lib/job-tags.ts에서 공고 제목+내용에서 기술 키워드(JavaScript, Python, AWS, Docker, React 등)를
  정규식으로 추출하여 JobListing.tags에 JSON 형태로 저장.
- CSV는 UTF-8 BOM 제거 후 파싱(향후 iconv-lite 등 인코딩 강화 예정).

4-3. 우선순위 공고 추천
-----------------------
파일: app/api/dashboard/priority-jobs/route.ts, components/dashboard/PrioritySection.tsx
- fitScore: 사용자 skills와 공고 tags/직무명의 교집합 비율(0~100)
- urgencyScore: 마감까지 남은 일수(7일 이하=100, 30일 이상=30, 그 사이 선형)
- competitionScore: 북마크 수 기반(0개=100, 1개당 10점 차감, 10개 이상=0)
- priorityScore = fit * 0.5 + urgency * 0.3 + competition * 0.2
- 상위 5개를 "오늘의 추천 공고"로 대시보드에 표시.

4-4. 자소서 코칭 시스템
-----------------------
파일: lib/cover-letter-analysis.ts, app/api/cover-letter/analyze/route.ts
- 11가지 항목 분석
  1. 분량(10): 200자 미만 경고, 1500자 초과 경고, 500~1200자 권장.
  2. 공허한 표현(15): "최선을 다하겠습니다", "열심히 하겠습니다" 등 cliché 감지.
  3. 수치/숫자(15): 숫자 포함 여부.
  4. STAR 기법(25): 상황/과제/행동/결과 키워드 포함 여부.
  5. 직군 키워드(20): 개발/데이터/사무/IT기획/보안 필수 키워드 포함 여부.
  6. 문장 길이(10): 150자 이상 문장 경고.
  7. 협업(5): 팀/협업/소통 등 단어 포함 여부.
  8~11. 첫 문장(저는으로 시작), 접속사 남용, 수동태(되었습니다 등), 추상적 형용사(다양한, 여러 등)
        → 패널티/보너스 표시, 점수에는 직접 반영하지 않음.
- 가중치 기반 0~100점 계산.
- good: 가중치 100%, warn: 40%, bad: 0%.
- 카테고리별 가장 나쁜 결과만 반영하여 중복 방지.
- CoverLetterVersion 모델로 버전 히스토리 저장.
- recharts로 점수 변화 그래프 시각화.

7-1. Gemini API 연동 시도 및 현황
================================================================================

- 목적:
  기존 키워드/룰 기반 자소서 코칭의 한계(문맥 이해, 문장 단위 개선 제안,
  공고 요약, 면접 질문 생성)를 보완하기 위해 Google Gemini API 도입을 시도 중.

- 시도 내용:
  * @google/generative-ai 패키지 추가 및 GOOGLE_API_KEY 환경변수 설정 검토.
  * lib/gemini.ts를 통한 Gemini Pro/Flash 모델 호출 래퍼 구현 계획.
  * /api/gemini/analyze API route 추가 계획.
  * 기존 /api/cover-letter/analyze에 Gemini 기반 문맥 피드백을 보조적으로 연동.

- 현재 상태:
  시도했으나 정상적으로 동작하지 않음.
  API 키, 모델 버전, 프롬프트, rate limit 등 추가 검증 및 디버깅 필요.

- 향후 활용 방안:
  * 자소서 문맥 기반 개선 제안
  * 채용 공고 요약 및 핵심 키워드 추출
  * 맞춤 면접 질문 및 모범 답안 생성
  * JD ↔ 자소서 적합도 문장 단위 분석

8-1. Gemini API 연동 마무리
---------------------------
- WHAT: Google Gemini 모델을 연결해 자소서 피드백, 공고 요약, 면접 질문 생성 등에 사용.
- WHY: 현재 키워드/룰 기반 분석은 문맥 이해와 문장 단위 개선 제안에 한계가 있음.
  * "최선을 다하겠습니다" 같은 표현이나 STAR 구조는 잡아내지만, 문맥상 어색한 문장,
    논리적 흐름, 구체적인 경험의 설득력 등은 판단하기 어려움.
  * 사용자가 "이 문장을 어떻게 고치지?"에 대한 직접적인 답변을 제공하려면
    생성형 AI의 문장 재작성/코칭 기능이 필요함.
- HOW:
  * @google/generative-ai 패키지 설치
    - npm install @google/generative-ai
    - package.json dependencies에 추가
  * 환경변수 설정
    - .env.example과 .env.local에 GOOGLE_API_KEY 추가
    - Vercel 배포 시 Environment Variables에도 등록
  * lib/gemini.ts 래퍼 생성
    - GoogleGenerativeAI 인스턴스 생성
    - model = genAI.getGenerativeModel({ model: 'gemini-1.5-flash' }) 권장
      (빠르고 저렴, 자소서/공고 분석 용도에 적합)
    - generateText(prompt) 함수로 추상화
    - rate limit, timeout, 재시도 로직 추가 권장
  * /api/gemini/analyze route 생성
    - POST /api/gemini/analyze
    - body: { prompt, type: 'cover-letter' | 'job-summary' | 'interview' }
    - 인증(session) 확인
    - Gemini 호출 후 텍스트 결과 반환
  * /api/cover-letter/analyze에서 Gemini 보조 연동
    - 기존 룰 기반 분석(feedback, overallScore)은 그대로 유지
    - 사용자가 "AI 코칭 보기"를 요청하면 Gemini로 추가 피드백 생성
    - 응답에 geminiFeedback?: { summary, suggestions, rewrittenExample } 추가
    - 프롬프트 예시: "다음 자기소개서 문항을 개발 직군 관점에서 코칭해줘.
      STAR 기법, 구체적 수치, 공허한 표현, 능동태 사용 여부를 중심으로 피드백하고,
      개선된 예시 문장 1~2개를 제시해줘."
- 변경 파일:
  * package.json
  * .env.example, .env.local
  * lib/gemini.ts (신규)
  * app/api/gemini/analyze/route.ts (신규)
  * app/api/cover-letter/analyze/route.ts (확장)
  * components/cover-letter/AIFeedbackPanel.tsx (선택, UI 추가)
- DB Schema 변경: 없음
- API 설계:
  * POST /api/gemini/analyze
    { prompt: string, type?: string } → { data: { result: string } }
  * POST /api/cover-letter/analyze (기존)
    body에 useGemini?: boolean 추가 → { ..., geminiFeedback?: {...} }
- 예상 난이도: 중
- 예상 소요 시간: 1~2일
- 참고/주의사항:
  * Google AI Studio(https://aistudio.google.com)에서 API 키 발급 필요
  * Gemini API는 무료 티어가 있으나, rate limit(분당/일별 요청 수) 확인 필요
  * serverless 환경에서 API 호출 시 timeout 주의 (Gemini 호출이 5~10초 걸릴 수 있음)
  * 프롬프트에 민감 개인정보(이름, 연락처)가 포함되지 않도록 마스킹 권장
  * API 키를 클라이언트에 노출하지 않도록 서버 API Route에서만 호출

8-3. 우선순위 점수 가중치 사용자 조절

  * 사용자 상황에 따라 선호하는 우선순위가 달라야 개인화된 대시보드가 됨.
- HOW:
  * 상태 저장
    - localStorage에 fitWeight, urgencyWeight, competitionWeight 저장
    - 로그인 사용자라면 User 모델에 preference 필드 추가해 DB 저장 가능
  * UI
    - components/dashboard/PrioritySection.tsx 상단에 3개 Slider 추가
    - shadcn Slider 컴포넌트 사용
    - 3개 슬라이더 합이 1이 되도록 실시간 정규화
    - "기본값 복원" 버튼 추가
  * API
    - GET /api/dashboard/priority-jobs?fit=0.5&urgency=0.3&competition=0.2
    - 쿼리 파라미터에서 가중치 파싱
    - 합이 1이 아니면 정규화
    - priorityScore = fit * w1 + urgency * w2 + competition * w3
  * 컴포넌트
    - PriorityJobCard에 현재 적용 가중치 노출(선택)
- 변경 파일:

  * app/api/dashboard/priority-jobs/route.ts

8-7. 엑셀 업로드 인코딩/CSV 강화

  * 한글 깨짐이나 컬럼 오류는 공고 등록 실패로 이어짐.
- HOW:
  * iconv-lite 추가
    - npm install iconv-lite
    - 파일 버퍼를 euc-kr, utf-8, utf-16 순으로 디코딩 시도

  * CSV 파서 교체

    - 따옴표, 줄바꿈, 쉼표 포함 셀 안정적 처리
    - BOM 제거
  * .xls/.xlsx/.csv 통일 파이프라인
    - 동일한 mapRow() 함수로 후처리
    - 파일 확장자에 따라 xlsx 또는 csv-parse 분기

8-8. 리크루터 실제 조회 페이지
-----------------------------
- WHAT: RECRUITER 계정이 학생 포트폴리오/자소서/프로필을 실제로 조회하는 화면.
- WHY:
  * 현재 리크루터 시점은 본인 화면에서만 토글로 확인 가능.
  * 실제 RECRUITER 계정의 UX가 없어 프리뷰 기능의 가치가 제한적.
  * 기업 담당자가 학생을 검색/열람하는 흐름을 완성해야 리크루터 기능이 실용적.
- HOW:
  * /api/recruiter/users/[id]/route.ts (신규)
    - GET /api/recruiter/users/[id]
    - 세션 role RECRUITER 확인
    - user, portfolio, coverLetter(공개 항목만) 조회
    - 리크루터에게 공개될 데이터만 필터링 (lib/visibility-config.ts 재사용)
    - 연락처 등 민감 정보 마스킹
  * app/(recruiter)/recruiter/users/[id]/page.tsx (신규)
    - 리크루터 전용 레이아웃
    - 학생 기본 프로필 카드
    - 포트폴리오 요약 (GitHub 분석 카드 포함)
    - 공개된 자소서 항목 리스트
    - 목록으로 돌아가기 버튼
  * 검색/목록 페이지 (선택)
    - /recruiter/users: 학생 검색/목록
    - 전공, 기술 스택, 포트폴리오 유무 등으로 필터
  * middleware.ts 수정
    - /recruiter/* 경로 접근 시 RECRUITER 또는 ADMIN 역할 확인
- 변경 파일:
  * app/api/recruiter/users/[id]/route.ts (신규)
  * app/(recruiter)/recruiter/users/[id]/page.tsx (신규)
  * app/(recruiter)/recruiter/users/page.tsx (선택, 신규)
  * lib/visibility-config.ts (확장)
  * middleware.ts (선택)
- DB Schema 변경: 없음
- API 설계:
  * GET /api/recruiter/users/[id]
    - RECRUITER 권한 확인
    - { user, portfolios, coverLetters } 반환 (마스킹/공개 설정 적용)
- 예상 난이도: 중
- 예상 소요 시간: 2~3일
- 참고/주의사항:
  * 학생 동의/공개 설정이 선행돼야 함 (자소서 전체 공개 vs 요약 공개 정책 필요)
  * 개인정보 보호법상 연락처, 이메일 등은 학생 동의 없이 노출 불가
  * 실제 리크루터 계정/정책이 있을 때 진행 권장

9. 총평
================================================================================

JobFilter는 AI API 비용 없이, 학과 특화 데이터와 키워드/룰 기반 분석으로
컴퓨터공학부 학생의 취업 준비 전 과정(공고 발굴 → 지원 관리 → 자소서 코칭 →
면접 준비 → 포트폴리오 분석)을 하나의 웹앱에서 지원하는 것을 목표로 한다.
Next.js 단일 코드베이스, Prisma/PostgreSQL, Vercel 배포로 운영 효율성을 높이고,
shadcn/ui와 Tailwind로 빠르고 일관된 UI를 구성했다.
