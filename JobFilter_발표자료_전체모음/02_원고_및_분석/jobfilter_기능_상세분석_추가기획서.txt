================================================================================
0. 최종 결론
================================================================================

JobFilter는 단순 채용공고 목록이 아니라 다음 4개 제품을 동시에 포함한다.

1) 컴퓨터·AI소프트웨어 학과 맞춤 공고 탐색기
2) 개인 지원 현황 관리 도구
3) 자소서 룰 기반 코칭 도구
4) 학생 취업 준비 통합 대시보드

현재 기능 수는 충분하다. 지금 필요한 것은 기능을 무조건 더 추가하는 것이 아니라,
사용자가 “공고 발견 → 저장 → 지원 준비 → 지원 → 후속 관리 → 결과 분석”을
끊김 없이 완료하게 만드는 연결 기능이다.

가장 추천하는 제품 방향:

- 1순위: 공고별 지원 준비 워크스페이스(Command Center)
- 2순위: 공고 변경/마감/면접/팔로업 통합 알림
- 3순위: 실제 리크루터 학생 탐색·프로필 조회 기능
- 4순위: 매칭 점수의 설명 가능성 개선
- 5순위: 지원 활동 분석과 개인별 개선 리포트

반대로 당장 추가하지 않는 것이 좋은 것:

- AI 챗봇/AI 자기소개서 자동 생성
- 여러 외부 채용 사이트의 무제한 자동 크롤링
- 소셜 피드·커뮤니티·팔로우 기능
- 화려한 차트만 늘리는 기능
- 실제 사용 흐름과 연결되지 않는 프로필 꾸미기 기능

현재 장점:
- 핵심 가치가 UI에 명확하게 드러난다.
- “공고를 찾고 내 지원 목록에 추가” 흐름이 짧다.
- 회사·직무·마감·경력·기술 매칭을 한 화면에서 볼 수 있다.

현재 문제:

1. 매칭 점수의 설명이 부족하다.
- “매칭 72%”만 표시하면 사용자는 무엇이 일치했고 무엇이 부족한지 모른다.
- 태그 수와 직무 단어를 단순 교집합으로 계산하므로 키워드 중복이나 긴 문자열
  포함 관계에 따라 점수가 왜곡될 수 있다.
- 대시보드 priority route와 listings page의 계산 기준이 서로 다르다.
- 추천 점수가 높아도 왜 높은지 설명이 없다.

개선:
- 매칭 점수를 `기술 일치`, `직무 일치`, `경력 적합`, `마감 여유`, `정보 신뢰도`로 분해한다.
- “일치 기술: React, TypeScript / 부족 기술: Docker”처럼 보여준다.
- 점수 계산을 lib/matching.ts 한 곳으로 통합한다.
- 각 점수에 사용된 근거를 API가 반환한다.

2. 필터 결과의 기준이 불명확하다.
- “CS 맞춤 필터링”이 어떤 규칙으로 이뤄졌는지 사용자에게 보이지 않는다.
- 공고가 왜 제외되었는지 관리자도 확인하기 어렵다.

개선:
- 공고 카드에 분류 근거 태그를 표시한다.
- 관리자 업로드 결과에 `포함/제외/중복/파싱 실패` 요약을 추가한다.
- 제외 키워드와 포함 키워드의 관리 화면을 추가한다.

3. 데이터 최신성 표시가 없다.
- source와 createdAt은 있지만 마지막 확인일, 원문 변경일, 만료 추정이 부족하다.
- 학교 엑셀은 스냅샷이므로 사용자는 현재 공고인지 알기 어렵다.

개선:
- `등록일`, `마지막 확인일`, `마감 확실성`, `원문 열기`를 표시한다.
- 오래된 공고에는 “정보 확인 필요” 라벨을 표시한다.

4. 목록이 커지면 클라이언트에서 전체 데이터를 내려받는다.
- 검색과 일부 필터가 클라이언트에서 동작한다.
- 공고 수가 늘면 페이지네이션, 서버 필터, 정렬이 필요하다.

개선:
- `q`, `deadline`, `career`, `employmentType`, `tags`, `sort`, `page`를 API에서 처리한다.
- total, page, pageSize를 반환한다.
- URL query string에 필터 상태를 저장해 새로고침/공유를 지원한다.

- 체크리스트 항목을 사용자가 추가/삭제/순서 변경

P1: 작업/리마인더 모델 분리

- 예: taskType, title, dueAt, completedAt, priority, note

- Notification에 unique key/type/referenceId를 추가한다.

P2: 결과 기록

현재 장점:
- AI 없이도 차별화된 기능을 구현했다.
- 단순 맞춤법 검사보다 취업 문맥에 가까운 피드백을 제공한다.
- 버전과 점수 변화가 있어 개선 과정을 볼 수 있다.

개선할 점:

1. 점수가 높아지는 것이 실제 품질 향상과 같지 않을 수 있다.
- 숫자·키워드를 억지로 넣어 점수만 높일 수 있다.
- 룰 기반 분석의 한계를 화면에 명확히 표시해야 한다.

2. 피드백에서 편집으로 연결되는 동작이 약하다.
- 히트맵 셀 클릭 → 해당 문항 이동 → 답변 내 키워드 하이라이트가 필요하다.
- “문제 해결” 버튼으로 해당 피드백 위치를 바로 열어야 한다.

3. 회사/직무별 자소서 템플릿이 부족하다.
- 사용자가 빈 문서에서 시작한다.
- 지원동기, 직무역량, 협업, 실패/성장, 입사 후 포부 템플릿을 제공하면 진입장벽이 낮아진다.

4. JD와 자소서 연결이 약하다.
- listings에서 회사/직무만 전달되고, description/tags 기반의 분석 컨텍스트를
  자소서에 연결할 수 있으면 더 강력하다.

5. 짧은 글 오탐 가능성
- 2~3 gram 유사도는 일반 문구와 짧은 문장에서 오탐이 생길 수 있다.
- “표절 확정”이 아니라 “유사 문구 참고”라고 표시해야 한다.

추천 기능:

P0: 코칭 결과 → 편집 연결
- 피드백마다 category, severity, targetItemIndex, targetTextRange를 반환
- 피드백 클릭 시 해당 문항으로 이동
- 대상 문장을 mark 처리
- 수정 후 해당 피드백만 재검사

P0: 공고 기반 자소서 준비 흐름
- 공고 상세에서 “이 공고로 자소서 시작” 클릭
- 회사/직무/JD 키워드/체크리스트를 연결
- 자소서 화면에 “이 공고의 핵심 요구사항” 표시
- 커버레터와 JobPosting을 항상 연결

P1: 답변 품질 개선 도구
- 문항별 글자 수/권장 길이
- 문장별 동사·수치·결과 표시
- 경험·행동·결과가 비어 있는 문항 강조
- 문장 분할 제안
- 유사 표현 사전 관리

P1: 템플릿과 경험 저장소
- 사용자의 경험을 별도 Experience 모델로 저장
- 경험 제목, 상황, 행동, 결과, 사용 기술, 수치, 협업 역할
- 여러 자소서 문항에서 같은 경험을 재사용하되 문장 중복을 경고
- AI 없이도 경험을 조합할 수 있다.

P2: 버전 비교
- 버전 A/B diff 보기
- 점수 변화뿐 아니라 추가/삭제/변경 문장 표시
- “점수는 올랐지만 키워드 과다” 같은 경고

부족한 점:

1. 모의 면접 결과가 학습 기록으로 남지 않는다.
- 어떤 질문을 받았고 답변했는지, 얼마나 걸렸는지, 다시 연습할 질문인지가 부족하다.

- 특정 회사/직무 면접을 준비하는 것이 아니라 일반 질문 모음에 머문다.

3. 답변 코칭이 약하다.
- 자소서 분석 엔진의 STAR 룰을 면접 답변에도 재사용할 수 있다.

4. 질문 우선순위가 없다.

추천 기능:

중요한 구현 문제:

1. 우선순위 가중치 입력 검증
- API는 fit/urgency/competition 값을 parse하지만 음수 값을 막지 않는다.
- 합계가 0이면 음수·비정상 점수가 만들어질 수 있다.
- 각 값을 0~1로 clamp하고 최소 한 항목 이상, 합계 정규화를 보장해야 한다.

2. 우선순위 점수의 경쟁도 해석
- 북마크 수가 적을수록 경쟁이 낮다고 가정한다.
- 실제 지원 경쟁률이 아니므로 사용자에게 “예상 경쟁도”라고 명시해야 한다.
- 북마크하지 않은 사용자는 집계되지 않으므로 편향이 크다.

3. 대시보드 점수와 목록 매칭 점수 불일치
- 동일 공고가 화면마다 다른 점수로 보일 수 있다.
- 계산 모듈과 반환 근거를 통합한다.

4. 알림이 수동 방문에 의존한다.
- 사용자 방문이 없으면 알림이 생성되지 않는다.
- 이메일/푸시를 바로 추가하기보다 먼저 scheduled sync와 앱 내 inbox를 안정화한다.

13. 0원 원칙을 유지하는 구체적 기능
================================================================================

다음은 외부 AI API 없이 구현 가능하다.

1. 설명 가능한 매칭
- 태그 교집합, 직무명, 경력, 고용형태, 마감일을 규칙으로 계산

2. 경험 저장소
- STAR 구조화 입력과 문장 재사용

3. 공고별 준비율
- 체크리스트 완료율, 필수 항목 미완료

4. 규칙 기반 자소서 개선
- 문장 길이, 수치, 행동 동사, 결과, 기술 키워드

5. 면접 복습 우선순위
- 미답변/오래된 답변/낮은 자기평가 기준

6. 공고 변경 감지
- 허용된 원문에 한정한 수동 확인과 hash 비교
- 자동 주기 호출은 cron 설정과 대상 수를 제한

7. 지원 활동 통계
- 기존 DB의 statusHistory와 createdAt/updatedAt 집계

8. ICS export
- 서버 비용 없이 파일 생성

15. 검증 지표
================================================================================

기능 추가 후 단순히 “페이지가 열린다”로 판단하지 않는다.

핵심 지표:
- 공고 목록 방문 → 북마크 전환율
- 공고 목록 → 지원 목록 추가율
- 지원 목록 추가 → 자소서 생성률
- 자소서 생성 → 분석 실행률
- 분석 실행 → 재수정률
- 지원 건의 체크리스트 완료율
- 면접 질문 답변 작성률
- 알림 확인 후 실제 상태 변경률
- 공고 변경 알림 확인률
- recruiter 공개 프로필 조회 → 관심 요청률

품질 기준:
- 매칭 점수는 근거를 함께 제공
- 공고 마감일이 지난 경우 목록/추천에서 일관되게 처리
- 모든 사용자의 데이터는 본인만 조회/수정
- recruiter는 동의된 필드만 조회
- 알림 중복 생성 없음
- 같은 작업을 새로고침해도 부작용 없음
- 모바일에서도 핵심 CTA가 보임
- 키보드로 폼/모달 사용 가능

16. 웹 조사 근거
================================================================================

1) LinkedIn Job Alerts
https://www.linkedin.com/help/linkedin/answer/a511279/
- 사용자의 검색 조건과 일치하는 새 공고를 알림으로 받는 흐름을 제공한다.
- JobFilter는 외부 사이트 연동보다 먼저 내부 공고의 저장 검색/새 공고 알림부터
  구현하는 것이 적합하다.

2) USAJOBS Job Alerts
https://help.usajobs.gov/how-to/search/job-alerts
- 조건 저장, 일/주/월 단위 알림, alert 수명 관리 사례를 확인할 수 있다.
- JobFilter의 향후 saved search는 빈도, 만료일, 일시중지 기능이 필요하다.

3) Careerflow Job Tracker
https://www.careerflow.ai/job-tracker
- 상태별 지원 관리, custom label, deadline/follow-up 관리가 일반적인 핵심 기능임을
  확인했다.
- JobFilter는 이미 일부를 구현했으므로 Command Center와 구조화된 task로 확장한다.

4) W3C WCAG 2.2
https://www.w3.org/TR/WCAG22/
- 폼, 키보드 접근, 오류, 포커스, 인지 가능성 기준을 기능 개선에 반영해야 한다.
- 회원가입, 프로필, 자소서, 공고 업로드는 특히 접근성 검증 대상이다.

5) Next.js Vitest Guide
https://nextjs.org/docs/14/app/building-your-application/testing/vitest
- Vitest와 React Testing Library 기반의 단위/UI 테스트를 기능 확장 전에 도입하는
  근거로 사용했다.

17. 최종 추천
================================================================================

가장 먼저 구현할 3개:

1. 지원 건 Command Center
- JobPosting 하나에서 자소서, 체크리스트, 포트폴리오, 면접, 일정, 상태 이력을
  모두 관리하도록 연결한다.

2. 설명 가능한 매칭 + 준비율
- “왜 이 공고가 나에게 맞는지”와 “무엇이 부족한지”를 보여준다.
- 단순 점수보다 신뢰도가 높고 구현 비용도 낮다.

3. 오늘의 할 일 + 구조화된 알림
- 마감, 면접, 팔로업, 미완료 준비물을 한 화면에 보여준다.
- GET 요청 부작용을 제거하고 명시적인 sync/스케줄링으로 안정화한다.

그 다음 차별화 기능:

4. 경험 저장소와 자소서 연결
5. 실제 recruiter 학생 탐색 및 동의 기반 관심 요청
6. 공고 변경 감지
7. 지원 결과 분석

이 순서가 좋은 이유:
- 현재 이미 존재하는 기능을 재사용한다.
- 새 DB 모델을 최소화하면서 사용자 가치가 크다.
- AI API 없이도 구현 가능하다.
- 기능이 서로 연결되어 재방문 이유를 만든다.
- 개인정보·운영 리스크가 큰 기능은 뒤로 미룰 수 있다.
