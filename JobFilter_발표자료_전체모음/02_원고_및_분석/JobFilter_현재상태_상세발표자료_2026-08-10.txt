발표 핵심 메시지

JobFilter는 단순히 채용공고를 보여주는 서비스가 아니라,
학생이 공고를 발견하고 지원 건으로 관리한 뒤 자소서·경험·면접·포트폴리오·일정까지
연결해 취업 준비를 진행할 수 있도록 돕는 학과 맞춤형 취업 준비 플랫폼이다.

발표 시 정확히 구분할 것

현재 구현
- 실제 소스와 API에서 동작을 확인한 기능

1차 구현
- 핵심 흐름은 동작하지만 세부 연결이 아직 부족한 기능

향후 계획
- 화면 이동 또는 기획만 있고 실제 데이터 연결이 끝나지 않은 기능

기술 스택
Next.js 14 · React · TypeScript · Prisma · PostgreSQL · NextAuth · Vercel

발표자 원고

안녕하세요. 지금부터 JobFilter의 현재 구현 상태와
오늘까지 진행한 기능 개선 내용을 발표하겠습니다.

JobFilter는 학교 취업지원처에서 제공하는 공고 중
컴퓨터·IT·개발 관련 공고를 선별하고,
학생의 목표 직무와 기술 스택을 기준으로 맞춤 공고를 보여주는 서비스입니다.

이번 작업의 핵심은 기능을 무작정 늘리는 것이 아니었습니다.
공고를 찾는 단계에서 끝나지 않고,
지원 건을 중심으로 자소서·경험·면접·포트폴리오·일정까지 연결하는 것이 목표였습니다.

SLIDE 02. 문제 정의
================================================================================

화면 표시 내용

학생 취업 준비의 문제

1. 학교 공고 Excel에는 전공과 무관한 공고가 섞여 있다.
2. 나에게 맞는 공고인지 판단하기 어렵다.
3. 공고별 자소서와 준비물이 여러 곳에 분산된다.
4. 자소서에서 부족한 부분을 객관적으로 찾기 어렵다.
5. 마감일·면접일·팔로업을 놓치기 쉽다.
6. 공고·자소서·면접·포트폴리오 사이의 연결이 약하다.

발표자 원고

학생들은 학교나 취업지원처에서 공고 파일을 받지만,
그 안에는 개발·사무·영업·서비스 등 여러 직무가 함께 들어 있습니다.

학생은 직접 자신에게 맞는 공고를 골라야 하고,
공고를 찾은 뒤에는 자소서와 면접, 일정, 포트폴리오를 각각 다른 문서나 메모로 관리합니다.

이렇게 되면 준비 과정이 끊기고,
무엇을 준비했고 무엇이 부족한지 한눈에 보기 어렵습니다.

JobFilter는 이 분리된 과정을 하나의 지원 준비 흐름으로 연결하는 데서 출발했습니다.

발표자 원고

JobFilter의 사용 흐름은 다음과 같습니다.

먼저 관리자가 학교 Excel 또는 CSV 공고를 업로드합니다.
시스템은 회사명과 직무를 매핑하고 IT·개발 관련 공고를 필터링합니다.

학생은 개인 프로필의 목표 직무와 기술 스택을 기준으로 공고를 비교합니다.
관심 공고는 북마크하거나 자신의 지원 목록에 추가할 수 있습니다.

지원 목록에 추가한 뒤에는 지원 건 상세에서
자소서, 체크리스트, 면접, 포트폴리오와 일정을 준비합니다.

핵심 가치
수많은 공고 중 나에게 맞는 공고를 빠르게 찾는다.

발표자 원고

맞춤 공고 화면에서는 회사명·직무·지역으로 검색할 수 있고,
마감일과 경력 조건을 필터링할 수 있습니다.

사용자의 기술 스택과 공고의 tags를 비교해서 매칭 점수를 계산합니다.
학생은 점수가 높은 공고를 우선 확인하거나,
마감일이 가까운 공고를 빠르게 찾을 수 있습니다.

관심 공고는 북마크하고,
바로 지원 목록에 추가할 수 있습니다.

학생의 기술과 공고 요구사항을 비교한 참고 지표입니다.

================================================================================

화면 표시 내용

빠른 이동

- 면접 연습
- 포트폴리오

발표자 원고

오늘 작업에서 가장 중요한 UI 개선 중 하나는
지원 건 상세에 Command Center를 추가한 것입니다.

기존에는 지원 공고와 자소서, 면접, 포트폴리오가 여러 화면에 분리되어 있었습니다.
이제 지원 건 상세에서 관련 준비 화면으로 바로 이동할 수 있습니다.

자소서 화면으로 이동할 때 회사명·직무명·jobId를 함께 전달합니다.
따라서 새 자소서를 만들 때 특정 지원 건과 연결할 수 있습니다.

다만 현재는 화면 이동과 자소서 연결이 중심인 1차 구현입니다.
포트폴리오와 면접 답변을 지원 건 데이터로 직접 집계하는 부분은 아직 향후 작업입니다.

SLIDE 09. 지원 준비 리포트 1차
================================================================================

화면 표시 내용

지원 준비 현황

- 자소서 연결
- 체크리스트 완료
- 면접 일정 설정
- 팔로업 일정 설정

준비율: 0~100%
최근 자소서 분석 점수: 표시

발표자 원고

지원 건 상세에는 준비 리포트 1차도 추가했습니다.

준비율은 네 가지 항목으로 계산합니다.
자소서가 연결되었는지,
체크리스트가 모두 완료되었는지,
면접 일정이 설정되었는지,
팔로업 일정이 설정되었는지를 확인합니다.

각 항목을 하나씩 계산해 25% 단위로 준비율을 표시합니다.

이 기능의 목적은 복잡한 새 시스템을 만드는 것이 아니라,
기존 데이터를 사용자가 이해하기 쉬운 진행 상태로 바꾸는 것입니다.

현재는 포트폴리오 프로젝트 수와 면접 답변 수까지는 준비율에 반영하지 않습니다.
이 부분은 명확히 향후 계획으로 구분합니다.

발표자 원고

자소서 코칭은 외부 AI API 없이 동작합니다.
분량·문장 길이·키워드·수치·STAR 패턴처럼
규칙 기반으로 1차 점검할 수 있는 항목을 분석합니다.

AI를 사용하지 않은 이유는 두 가지입니다.
첫째, 무료 학생 서비스를 지속 운영하기 위한 비용을 줄이기 위해서입니다.
둘째, 분석 기준을 학생과 발표자가 설명할 수 있도록 하기 위해서입니다.

다만 룰 기반 분석은 문맥을 완전히 이해하지 못합니다.
따라서 합격 판정이 아닌 작성 보조 피드백으로 안내합니다.

부록 B. 예상 질문과 답변
================================================================================

Q1. 왜 AI를 사용하지 않았나요?

A.
분량·키워드·문장 길이·STAR 구조는 룰 기반으로 1차 피드백을 제공할 수 있습니다.
외부 AI API 비용을 줄이고 분석 기준을 설명 가능하게 만들기 위해서입니다.
다만 문맥 판단에는 한계가 있어 합격 판정이 아닌 작성 보조로 안내합니다.

Q2. 매칭 점수는 정확한가요?

A.
합격 가능성을 의미하지 않습니다.
사용자 기술과 공고 기술·직무·경력·마감 조건을 비교한 참고 지표입니다.
일치 기술과 부족 기술을 함께 보여주는 것이 핵심입니다.

Q3. 지원 준비율은 무엇을 기준으로 하나요?

A.
현재 1차 버전은 자소서 연결, 체크리스트 완료,
면접 일정, 팔로업 일정 네 가지를 기준으로 계산합니다.
향후 포트폴리오와 면접 답변까지 추가할 예정입니다.

Q4. 경험 저장소는 왜 필요한가요?

A.
학생의 프로젝트 경험을 상황·행동·결과·기술·성과로 구조화해
여러 자소서와 면접 답변에서 재사용하기 위해서입니다.

Q5. 개인정보는 어떻게 보호하나요?

A.
각 API에서 세션·role·userId 소유권을 서버에서 검사합니다.
리크루터는 승인된 계정만 공고를 등록할 수 있고,
학생 탐색 기능은 공개 동의와 마스킹을 먼저 구현해야 합니다.

Q6. 왜 업로드 미리보기가 필요한가요?

A.
학교 Excel에는 중복·날짜 오류·무관 공고가 섞일 수 있기 때문입니다.
등록 전에 파싱 성공·제외·중복 결과를 확인하고 필요한 행만 등록합니다.

Q7. 현재 가장 부족한 부분은 무엇인가요?

A.
실제 API 통합 권한 테스트, 운영 DB migration 적용 확인,
포트폴리오·면접 답변의 지원 건 직접 연결,
전체 API DTO 정리가 남아 있습니다.
