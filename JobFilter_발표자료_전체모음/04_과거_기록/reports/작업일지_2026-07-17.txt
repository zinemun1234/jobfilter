[안건 05] 지금 당장 지원해야 할 공고 점수
---------------------------------------------
목적: 활성 공고 중 사용자가 지금 당장 지원해야 할 공고를 점수로 정렬해 대시보드 상단에 노출

점수 산출 공식:
  - fitScore: 사용자 skills와 JobListing.tags의 교집합 비율 (0~100)
  - urgencyScore: 마감일까지 남은 일수 (7일 이하=100, 30일 이상=30, 그 사이 선형)
  - competitionScore: 북마크 수 역수 (0개=100, 10개 이상=0, 사이는 10점씩 차감)
  - priorityScore = fitScore * 0.5 + urgencyScore * 0.3 + competitionScore * 0.2

신규 파일:
  - app/api/dashboard/priority-jobs/route.ts
      * GET /api/dashboard/priority-jobs
      * 인증 세션 → 사용자 skills 조회 → isActive=true, deadline>=today인 JobListing 조회
      * Prisma _count.bookmarks로 북마크 집계
      * priorityScore 기준 상위 5개 반환

  - components/dashboard/PriorityJobCard.tsx
      * 공고 카드 UI: 순위, 회사/직무, priorityScore, 세부 점수(fit/urgency/competition), D-day/북마크 수, 태그

  - components/dashboard/PrioritySection.tsx
      * 'use client', CSR로 /api/dashboard/priority-jobs 호출
      * 로딩/빈 상태 처리, 대시보드에 "오늘의 추천 공고" 섹션으로 배치

수정 파일:
  - app/(dashboard)/dashboard/page.tsx
      * import PrioritySection 추가
      * 히어로 배너 아래 max-w-5xl 영역에 <PrioritySection /> 삽입

5. 제약사항 및 후속 고려사항
=============================================================

- "리크루터 시점 미리보기"는 기존에 실제 리크루터가 학생 프로필/포트폴리오/자소서를 조회하는 화면이 없어,

  추후 실제 리크루터 뷰(/recruiter/users/[id])가 추가되면 해당 페이지에서 동일한 마스킹 로직 재사용 가능.

- 히트맵은 공고(JoListing)를 드롭다운으로 직접 선택. CoverLetter의 jobId는 JobPosting을 연결하므로
  JobListing과 자동 매핑이 불가능했음. 사용자가 직접 비교 대상 공고를 선택하는 UX로 처리.

- 추천 공고 점수는 사용자 skills가 비어 있으면 fitScore가 0이 되므로, 스킬 입력 권장.

- 실제 UI/데이터 흐름 확인은 로그인 후 /dashboard, /cover-letter, /profile?view=recruiter에서 진행 필요.
