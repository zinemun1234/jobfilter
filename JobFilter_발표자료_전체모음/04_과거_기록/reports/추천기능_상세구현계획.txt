프로젝트 개요

JobFilter는 컴퓨터공학부 학생을 위한 맞춤 취업 공고 필터링 & 자소서 코칭 웹앱입니다.

이 문서는 기존 JobFilter에 추가할 수 있는 기능 8가지에 대한 상세 구현 계획을 정리한 것입니다.
기존 핵심 전제(서버 비용 0원, AI 없이 키워드/룰 기반)를 유지하는 방향으로 작성되었습니다.

## 1. 공고 변경 감지 (Diff 알림)

목적
사용자가 북마크한 공고의 원본 URL을 주기적으로 확인하여 JD 내용이나 마감일이 변경된 경우 알림을 생성하는 기능입니다.

배경
학교 취업지원처에서 제공하는 엑셀은 특정 시점의 스냅샷입니다.
기업이 공고 내용을 수정하거나 조기 마감할 경우 학생이 변경 사실을 인지하지 못하는 경우가 있습니다.

조치
1. Prisma schema의 `JobBookmark` 모델에 `lastCheckedAt`, `lastContentHash` 필드를 추가합니다.
2. `POST /api/cron/job-change-detection` API를 추가하고, Vercel Cron 또는 node-cron으로 6시간 간격 실행합니다.
3. 북마크된 `JobListing.url`을 fetch하여 본문 텍스트를 추출합니다.
4. 추출한 텍스트를 정규화(공백 제거, 소문자 변환)한 뒤 SHA-256 해시를 생성합니다.
5. 이전 해시와 다르면 변경으로 간주하고 `UserNotification` 레코드를 생성합니다.
6. 변경된 부분은 `diff-match-patch` 또는 `diff` 패키지로 before/after를 출력합니다.

적용 기술
- 데이터 저장: Prisma, PostgreSQL
- 스케줄링: Vercel Cron 또는 node-cron
- 본문 추출: Node.js fetch + cheerio 또는 html-to-text
- 해시 비교: crypto.createHash('sha256')
- diff 출력: npm diff-match-patch 또는 diff
- 알림: 기존 UserNotification 테이블

API 설계
- `POST /api/cron/job-change-detection`
  - 입력: 없음(cron 트리거)
  - 로직: 북마크된 공고 중 `lastCheckedAt`이 6시간 이상 지난 항목만 fetch
  - 결과: 변경된 공고에 대해 notification 생성
- `GET /api/notifications` (기존)
  - diff 요약(예: `변경: 마감일 2026-08-01 → 2026-07-25`) 포함

변경 파일
- `prisma/schema.prisma`: `JobBookmark`, `JobListing` 필드 추가
- `app/api/cron/job-change-detection/route.ts`: 신규
- `app/(dashboard)/notifications/page.tsx`: 공고 변경 알림 카드 추가
- `app/api/notifications/route.ts`: diff 요약 포함

DB Schema 변경
```prisma
model JobBookmark {
  ...
  lastCheckedAt   DateTime? // 마지막 확인 시각
  lastContentHash String?   // 마지막 본문 해시
}

model JobListing {
  ...
  previousDescription String? // 이전 본문(선택, diff 용)
}
```

기대 효과
- 북마크한 공고의 변경 사항을 누락하지 않고 확인할 수 있습니다.
- 공고 마감일 연장이나 조기 마감에 대해 신속히 대응할 수 있습니다.

참고
- cron 환경은 로컬 개발과 Vercel 배포 환경에 따라 분기 처리가 필요합니다.
- 공고 페이지의 HTML 구조가 변경되면 본문 추출 로직이 실패할 수 있습니다.

난이도 및 우선순위
- 난이도: 중
- 우선순위: 높음

## 2. JD ↔ 자소서 키워드 매칭 히트맵

목적
공고 JD의 키워드가 자소서의 어떤 문항에, 얼마나 포함되어 있는지 색상(히트맵)으로 보여주는 기능입니다.

배경
자소서 코칭이 전반적인 문장 평가에 머물러 있어, 문항별 JD 키워드 누락을 직관적으로 파악하기 어렵습니다.
문항별 키워드 분포를 시각화해야 어디를 보강할지 빠르게 결정할 수 있습니다.

조치
1. 공고 `tags` 또는 `description`에서 기술/역량 키워드를 추출합니다.
2. 자소서 `items`(질문/답변 배열)의 각 문항에 대해 키워드 등장 횟수를 카운트합니다.
3. 문항 × 키워드 매트릭스를 생성합니다.
4. 등장 횟수에 따라 색상 농도(흰색 → 노랑 → 빨강)를 지정합니다.
5. 셀 클릭 시 해당 문항으로 스크롤하고 키워드를 하이라이트합니다.

적용 기술
- 키워드 추출: `lib/cover-letter-analysis.ts`의 키워드 매칭 로직 재사용
- 히트맵 UI: CSS Grid + Tailwind background-color 단계별 설정
- 하이라이트: DOM scrollIntoView + 문자열 기반 span 하이라이트
- 데이터: `CoverLetter.items` JSON + `JobListing.tags`

API 설계
- `POST /api/cover-letter/keyword-heatmap`
  - 입력: `{ coverLetterId, jobListingId }`
  - 출력: `{ keywords: string[], matrix: number[][] }`

변경 파일
- `app/(dashboard)/cover-letter/[id]/page.tsx`: 히트맵 사이드바 추가
- `app/(dashboard)/cover-letter/[id]/KeywordHeatmap.tsx`: 신규
- `app/api/cover-letter/keyword-heatmap/route.ts`: 신규
- `lib/cover-letter-analysis.ts`: 키워드 카운트 함수 추가

기대 효과
- 자소서 문항별 JD 키워드 누락을 한눈에 파악할 수 있습니다.
- 자소서 보강 방향을 데이터 기반으로 제시할 수 있습니다.

참고
- 히트맵은 클라이언트에서 렌더링하며, 데이터는 API에서 계산합니다.
- 키워드 매칭은 단순 문자열 포함 여부로 판단하며, 형태소 분석은 사용하지 않습니다.

난이도 및 우선순위
- 난이도: 하~중
- 우선순위: 높음

## 3. GitHub 포트폴리오 자동 분석 카드

목적
포트폴리오에 등록한 GitHub URL을 분석하여 주 사용 언어 비율, 커밋 활동, README 존재 여부, 최근 업데이트일 등을
시각 카드로 자동 채우는 기능입니다.

배경
학생이 포트폴리오를 손으로 채우면 주관적이거나 실제와 불일치하는 정보가 포함될 수 있습니다.
GitHub 활동을 객관적 증거로 보여주면 리크루터 신뢰도가 상승합니다.

조치
1. `Portfolio` 모델의 `githubUrl`에서 owner/repo를 파싱합니다.
2. GitHub REST API `/repos/{owner}/{repo}`를 호출합니다.
3. 언어 비율은 `/repos/{owner}/{repo}/languages`에서 조회합니다.
4. 커밋 통계는 `/repos/{owner}/{repo}/commits` 최근 30개를 조회합니다.
5. README는 `/repos/{owner}/{repo}/readme`를 base64 디코딩하여 길이를 측정합니다.
6. 분석 결과를 `Portfolio` 테이블의 JSON 필드에 캐싱합니다.
7. 포트폴리오 상세/목록에 시각 카드를 추가합니다.

적용 기술
- API: GitHub REST API v3(공개 repo, 인증 토큰 없이 가능)
- 요청: Next.js API Route에서 fetch 사용
- 파싱: 정규식으로 `https://github.com/{owner}/{repo}` 추출
- 캐싱: `Portfolio.githubAnalysis` JSON 필드 + `githubAnalyzedAt` 시각
- 차트: recharts로 언어 비율 파이/도넛 차트

API 설계
- `POST /api/portfolio/analyze-github`
  - 입력: `{ portfolioId }`
  - 출력: `{ languages: {lang: bytes}[], totalCommits: number, readmeLength: number, lastPush: Date }`
  - 인증: 선택, `GITHUB_TOKEN` 환경변수(비공개 repo 대비)

변경 파일
- `app/api/portfolio/analyze-github/route.ts`: 신규
- `app/(dashboard)/portfolio/[id]/page.tsx`: GitHub 분석 패널 추가
- `app/(dashboard)/portfolio/export/page.tsx`: 요약 데이터 포함
- `prisma/schema.prisma`: `Portfolio` 모델에 필드 추가

DB Schema 변경
```prisma
model Portfolio {
  ...
  githubAnalysis   Json?      // 언어, 커밋, README 정보 캐시
  githubAnalyzedAt DateTime?
}
```

기대 효과
- 포트폴리오의 기술 스택과 활동량을 객관적 데이터로 제시할 수 있습니다.
- 포트폴리오 export 시 요약 데이터를 함께 출력할 수 있습니다.

참고
- GitHub API rate limit은 공개 repo도 분당 60회로 제한됩니다.
- 캐싱 주기는 7일로 설정하여 불필요한 API 호출을 줄입니다.

난이도 및 우선순위
- 난이도: 하
- 우선순위: 중

## 4. 리크루터 시점 미리보기

목적

## 5. 지금 당장 지원해야 할 공고 점수

목적
대시보드에 "오늘/이번 주 지원 우선순위 Top N"을 매칭률 + 마감 임박 + 북마크 기반 경쟁률로 계산하여 보여주는 기능입니다.

배경
공고가 많아지면 어떤 공고를 먼저 지원해야 할지 결정이 어렵습니다.
단순 마감 임박순이나 매칭률순이 아닌, 다중 지표로 우선순위를 산출해야 합니다.

조치
1. 각 공고에 대해 아래 3가지 점수를 계산합니다.
   - `fitScore`: 사용자 `skills`와 공고 `tags`의 교집합 비율(0~100)
   - `urgencyScore`: 마감일까지 남은 일수 기반(예: 7일 남으면 100, 30일 남으면 30)
   - `competitionScore`: 북마크 수 기반 역수, 북마크가 적을수록 높음
2. 가중 합으로 `priorityScore = fit*0.5 + urgency*0.3 + competition*0.2`를 계산합니다.
3. 상위 N개를 대시보드에 노출합니다.
4. (선택) 사용자가 가중치를 슬라이더로 조정할 수 있도록 합니다.

적용 기술
- 점수 계산: Next.js API Route 또는 서버 컴포넌트에서 Prisma aggregation
- 가중치 저장: Zustand 또는 localStorage(선택)
- UI: 대시보드 상단 "오늘의 추천 공고" 카드 + progress bar
- 차트: Radix Progress, Badge

API 설계
- `GET /api/dashboard/priority-jobs`
  - 인증된 사용자의 skills 조회
  - 활성 공고(`isActive=true`, `deadline >= today`) 필터
  - 각 공고의 북마크 수 집계(`_count.bookmarks`)
  - 점수 계산 후 상위 5개 반환

변경 파일
- `app/api/dashboard/priority-jobs/route.ts`: 신규
- `app/(dashboard)/dashboard/page.tsx`: PrioritySection 추가
- `components/dashboard/PriorityJobCard.tsx`: 신규

DB Schema 변경
- 없음(북마크 수는 Prisma relation count 사용)

기대 효과
- 사용자가 우선순위 높은 공고를 빠르게 식별할 수 있습니다.
- 대시보드 첫 화면에서 즉시 가치를 제공할 수 있습니다.

참고
- 가중치는 초기값으로 0.5/0.3/0.2를 사용하며, 사용자 조정을 허용할 수 있습니다.
- 조회 수 데이터가 없으므로 현재는 북마크 수로 경쟁률을 추정합니다.

난이도 및 우선순위
- 난이도: 하~중
- 우선순위: 높음

## 6. 자소서 중복/자기표절 경고

목적
여러 기업에 지원할 때 자소서 문항 간 중복 문장을 검사하여 유사도가 높은 쌍을 경고하는 기능입니다.

배경
다중 지원 시 학생들이 같은 경험이나 문장을 그대로 복사하여 붙여넣는 경우가 많습니다.
기업별 맞춤형 차별화가 부족하면 서류 합격률이 떨어집니다.

조치
1. 사용자의 모든 `CoverLetter.items`를 파싱하여 문항별 텍스트를 수집합니다.
2. 문항 쌍 간 유사도를 계산합니다. LCS(최장 공통 부분 순열) 또는 n-gram 코사인 유사도를 사용합니다.
3. 임계값(예: 70%) 이상인 쌍을 경고 리스트로 생성합니다.
4. 중복된 부분을 하이라이트하고, 기업별 차별화 방향을 제시합니다.
5. `CoverLetterVersion` 히스토리도 비교 대상에 포함할 수 있습니다.

적용 기술
- 텍스트 전처리: 한글/영문 정규화, 조사 제거(선택)
- 유사도: LCS 구현 또는 `string-similarity` npm 패키지
- n-gram: 3-gram 기반 코사인 유사도(서버 비용 0원)
- 하이라이트: react-highlight-words 또는 자체 구현

API 설계
- `POST /api/cover-letter/duplicate-check`
  - 입력: `{ coverLetterId }`(현재 작성 중인 자소서 기준)
  - 출력: `{ duplicates: [{ otherId, otherCompany, otherPosition, similarity, matchedSentences }] }`
- `GET /api/cover-letter/duplicates`
  - 출력: 중복 의심 목록 조회

기대 효과

- 기업별 차별화 작성을 유도할 수 있습니다.

## 7. 공고별 마이크로 체크리스트

목적
공고 description에서 "포트폴리오", "성적증명서", "자격증", "경력증명서" 등 제출 서류 키워드를 자동 추출하여
지원 준비물 체크리스트를 생성하고 완료율을 관리하는 기능입니다.

배경
공고마다 요구하는 서류가 다릅니다.
학생이 일일이 메모하지 않아도 어떤 서류를 준비해야 하는지 자동으로 정리할 필요가 있습니다.

조치
1. `JobListing.description` 텍스트를 분석합니다.
2. 키워드 사전(`lib/application-checklist-keywords.ts`)을 정의합니다.
   - 예: `포트폴리오`, `portfolio`, `성적증명서`, `자격증`, `경력증명서`, `추천서`, `이력서`, `자기소개서`
3. 키워드별 카테고리를 매핑합니다.
4. `JobPosting`에 연결된 체크리스트 항목을 자동 생성합니다.
5. 사용자가 체크/해제하면 `ApplicationChecklist` 테이블에 저장합니다.
6. 공고 카드/지원 현황 테이블에 완료율 progress bar를 표시합니다.

적용 기술
- 키워드 추출: 정규식 + 사전 매칭
- 체크리스트 저장: Prisma `ApplicationChecklist` 모델
- UI: shadcn Checkbox + Progress

API 설계
- `POST /api/jobs/[id]/checklist`
  - body: `{ items: [{ label, checked, category }] }`
- `GET /api/jobs/[id]/checklist`
  - 출력: 체크리스트 목록
- `POST /api/jobs/[id]/checklist/auto-generate`
  - description에서 키워드를 추출하여 기본 체크리스트를 생성

변경 파일
- `app/api/jobs/[id]/checklist/route.ts`: 신규
- `app/api/jobs/[id]/checklist/auto-generate/route.ts`: 신규
- `app/(dashboard)/jobs/[id]/page.tsx`: 체크리스트 편집 UI 추가
- `app/(dashboard)/dashboard/page.tsx`: 지원 현황 테이블에 "준비율" 컬럼 추가
- `lib/application-checklist-keywords.ts`: 신규
- `prisma/schema.prisma`: `ApplicationChecklist` 모델 추가

DB Schema 변경
```prisma
model ApplicationChecklist {
  id        String   @id @default(cuid())
  jobId     String
  userId    String
  label     String
  category  String
  checked   Boolean  @default(false)
  isAuto    Boolean  @default(false)
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  job JobPosting @relation(fields: [jobId], references: [id], onDelete: Cascade)
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
}
```

기대 효과
- 공고별 서류 준비물을 누락 없이 관리할 수 있습니다.
- 지원 현황 테이블에서 준비율을 한눈에 확인할 수 있습니다.

참고
- 키워드 사전은 향후 추가/수정이 필요합니다.
- 자동 생성 항목은 사용자가 직접 편집할 수 있어야 합니다.

난이도 및 우선순위
- 난이도: 하~중
- 우선순위: 중
