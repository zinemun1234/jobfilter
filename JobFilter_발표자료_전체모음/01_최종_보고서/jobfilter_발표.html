Part 01

사업 개요

JobFilter는 컴퓨터공학부 학생을 위한 맞춤 취업 공고 필터링 & 자소서 코칭 웹 애플리케이션이다.

공고 필터링

학교 취업지원처 엑셀/CSV 파일 업로드 시 개발·IT·보안·데이터·기획 직군만 자동 추출

매칭 & 우선순위

기술 스택 기반 매칭률, 마감 D-day, 경쟁 점수로 상위 5개 추천 공고 노출

자소서 코칭

AI 없이 키워드/룰 기반으로 분량, STAR, 수치, 공허 표현, 직군 키워드, 문장 길이 등 체크

통합 취준 관리

지원 현황, 면접 준비, 기술 스택 로드맵, 포트폴리오 분석, 북마크, 알림까지 한 곳에서

대상 학과: 안산대학교 컴퓨터정보과, 인공지능소프트웨어과

Part 01

시장 환경 및 해결 과제

학교 취업지원처 엑셀에는 CS와 무관한 직군도 섞여 있다.

  • 필터링 번거로움: 학생들이 직접 무관한 직군을 걸러내며 맞는 공고를 놓치기 쉬움
  • 자소서 약점 파악 어려움: STAR 기법, 수치, 공허 표현 등을 스스로 판단하기 어려움
  • AI API 비용 부담: OpenAI/Claude 등을 사용하면 학생 대상 무료 서비스 지속 운영이 부담스러움
  • 준비물 관리: 서류, 포트폴리오, 자격증을 공고별로 따로 관리하기 어려움
Part 02

핵심 설계 철학

0원 서버 비용

AI API 사용 금지. 자소서 코칭, 공고 필터링, 키워드 추출, 우선순위 산정 등 핵심 기능을 모두 키워드 매칭, 정규식, 룰 기반으로 구현

기술 스택 및 선정 이유

Next.js 14 (App Router)

SSR/CSR/API Routes를 하나의 코드베이스로 처리할 수 있어 학교 또는 소규모 팀 운영에 적합

클라이언트 상태와 서버 상태를 분리하여 관리. 캐싱과 낙관적 업데이트로 UX 향상

recharts xlsx vitest

Part 03

우선순위 공고 추천

priorityScore = fit * 0.5 + urgency * 0.3 + competition * 0.2

fitScore

사용자 skills와 공고 tags/직무명의 교집합 비율(0~100)

urgencyScore

마감까지 남은 일수. 7일 이하=100, 30일 이상=30, 그 사이 선형 감소

competitionScore

북마크 수 기반. 0개=100, 1개당 10점 차감, 10개 이상=0

대시보드

상위 5개를 "오늘의 추천 공고"로 components/dashboard/PrioritySection.tsx에 표시

Part 03

자소서 코칭 시스템

lib/cover-letter-analysis.ts & app/api/cover-letter/analyze/route.ts

11가지 분석 항목

  • 분량(10): 200자 미만/1500자 초과 경고, 500~1200자 권장
  • 공허한 표현(15): "최선을 다하겠습니다", "열심히 하겠습니다" 등 cliché 감지
  • 수치/숫자(15): 구체적 수치 포함 여부
  • STAR 기법(25): 상황/과제/행동/결과 키워드 포함 여부

추가 항목

  • 직군 키워드(20): 개발/데이터/사무/IT기획/보안 필수 키워드
  • 문장 길이(10): 150자 이상 문장 경고
  • 협업(5): 팀/협업/소통 등 단어 포함 여부
  • 첫 문장, 접속사 남용, 수동태, 추상적 형용사는 패널티/보너스 표시

good=가중치 100%, warn=40%, bad=0%로 0~100점 산출. 카테고리별 가장 나쁜 결과만 반영해 중복 방지. CoverLetterVersion으로 버전 히스토리 저장, recharts로 점수 변화 시각화

Part 03

히트맵 & 포트폴리오 & 체크리스트

JD ↔ 자소서 키워드 히트맵

공고 tags와 description에서 사전 기반 기술 키워드 추출 → 자소서 각 문항 등장 횟수 카운트 → 문항×키워드 매트릭스로 시각화(0회=회색, 1회=노랑, 2회 이상=빨강)

GitHub 포트폴리오 분석

lib/github-analysis.ts에서 GitHub URL의 owner/repo 파싱 → REST API로 언어 비율, 커밋 수, README/라이선스, 마지막 push 일자 기반 활동 상태 분석 → components/portfolio/GitHubAnalysisCard.tsx에 시각화(7일 캐싱 권장, 공개 저장소 60회/시간 rate limit)

공고별 마이크로 체크리스트

lib/job-checklist.ts에서 공고 description과 tags로 13개 항목(포트폴리오, 자기소개서, 이력서, 성적증명서, 자격증, 추천서, 경력증명서, 토익/토플, GPA, 제안서, 사진, 신분증, 건강검진) 자동 추출 → JobPosting.checklist JSON에 저장 → 상세 페이지에서 토글로 완료 관리

자소서 중복/자기표절 경고

lib/cover-letter-duplicate.ts에서 여러 문항 간 유사 표현/중복 문구를 감지하여 사용자에게 경고

Part 03

면접 & 지원 현황 & 로드맵 & 알림

면접 준비

기술/인성/상황 × 프론트엔드/백엔드/공통으로 기본 질문 제공. 사용자가 커스텀 질문 추가/삭제, 답변 저장, 랜덤 모의 면접 진행

기술 스택 로드맵

Part 06

향후 추진 계획 (1/2)

1. Gemini API 마무리

WHY: 키워드/룰 기반은 문맥 이해와 문장 단위 개선 제안에 한계.

HOW: @google/generative-ai 설치 → lib/gemini.ts 래퍼 → /api/gemini/analyze → 기존 자소서 분석 API에 useGemini 옵션 추가. 모델 gemini-1.5-flash 권장. API 키는 서버에서만 사용.

예상: 난이도 중 / 1~2일

2. 공고 변경 감지

WHY: 북마크한 공고의 JD/마감일이 변경되어도 현재는 추적하지 않음.

HOW: JobBookmark에 lastCheckedAt, lastContentHash 추가 → /api/cron/job-change-detection에서 6시간마다 URL 본문 해시 비교 → 변경 시 UserNotification 생성. Vercel Cron 유료이므로 Upstash/GH Actions/수동 버튼 대체 가능.

예상: 난이도 중 / 2~3일

Part 06

향후 추진 계획 (2/2)

3. 우선순위 가중치 조절

PrioritySection에 shadcn Slider 3개 추가, 합=1 정규화. API에 fit/urgency/competition 쿼리 파라미터 추가. localStorage 또는 User preferences 저장.

4. 체크리스트 준비율 노출

/api/jobs 응답에 checklistProgress 추가 → 목록/대시보드 Progress 컴포넌트 표시. 0%는 "준비 시작" 문구로 부드럽게 처리.

5. 히트맵 ↔ 문항 하이라이트

KeywordHeatmap에 onHighlight prop → CoverLetter 페이지에서 scrollIntoView + <mark> 태그로 키워드 강조.

6. 문장 단위 피드백 하이라이트

분석 결과에 spans: { start, end, level, category } 추가 → CoachingGuide 클릭 시 해당 문장으로 스크롤, level별 배경색 적용.

7. 엑셀 인코딩/CSV 강화

iconv-lite, csv-parse 추가 → euc-kr/utf-8/utf-16 자동 디코딩 시도, 따옴표/줄바꿈 처리, 실패 행 요약 응답.

8. 리크루터 실제 조회 페이지

/api/recruiter/users/[id] + /recruiter/users/[id]/page.tsx 생성. lib/visibility-config.ts 마스킹 규칙 적용, 학생 동의/공개 정책 선행 필요.
